# Subtitle follow-up verification

The reviewed subtitle checkpoint is `79bf9bbfb89fd87053aaf2b161d551652b767423` on `codex/mediastrike-subtitles`. The follow-up branch `codex/mediastrike-subtitles-verification` starts from that checkpoint and keeps it intact. [Hosted Windows run 38821180745](https://github.com/Gerbzz/MediaStrike/actions/runs/38821180745) passed against follow-up commit `c75e63f8e3825f5ea3a21f5b018a01e55ed6758d`: nine ordinary tests, six generated-media tests, native build, and artifact upload. The runner generated media locally with GStreamer; no user media was used.

The generated-media checks covered decoded AVI playback and queue advance; external SRT discovery, text Off and re-selection; a Matroska file containing two distinct embedded SRT tracks, switching between them and Off; canceled and missing file choices; malformed nonempty SRT failures that arrive asynchronously; valid SRT choice while playing; valid WebVTT choice while paused; position and pause-state retention; and Repeat one retaining an external file, a selected embedded stream, and Off. The file-choice tests call the same app method used by the picker after it returns. They do not operate the Windows file dialog or click the Subtitles menu.

The malformed SRT exposed a real failure in the original subtitle branch: opening a replacement returned before GStreamer reported the parsing error, while the old playable pipeline had already been discarded. The follow-up keeps the current player until a candidate has completed preroll and reports a usable text stream. On error or timeout it keeps the current player. Same-item repeat seeks the existing pipeline instead of reopening the media, preserving its subtitle choice.

Two later tests reproduced a selection race on commit `bf4aa1e7b38e19d2be40997cbd7863e88324d5ed`: [hosted run 38822849885](https://github.com/Gerbzz/MediaStrike/actions/runs/38822849885) loaded a valid external SRT candidate, then chose Off or the second embedded track through the app's menu handler. Both choices were overwritten when the candidate replaced the active player. A successful newer Off or track choice now cancels that pending replacement; an unsuccessful choice leaves it pending. The tests use generated media and the menu's selection method, not native pointer clicks.

The [original SRT and WebVTT captures](SUBTITLE_CAPTURE_PROVENANCE.md) remain tied to source commit `f27f94d8e574885f5f5fd5d6fa29ae584d283482`. [Fresh captures](SUBTITLE_FINAL_CAPTURE_PROVENANCE.md) from `c48564ea5edc81edfd233f5213c589a1e3857ffc` verify initial SRT and WebVTT rendering after the follow-up repairs. Actual menu clicks, Windows dialog cancellation, audible output, caption timing, and more subtitle formats still need hands-on review.
